# SwitchBot 認証パッド 時間管理システム

SwitchBot の認証パッド（Keypad / Keypad Touch）のパスコードを、時間帯で自動管理します。
ブラウザでスケジュールを管理し、指定時刻に**パスコードを作成**、終了時刻に**削除**します。

* 毎日 / 毎週（曜日指定）/ 日付指定の3種類の繰り返し
* 時間帯指定（22:00→06:00 のような日跨ぎにも対応）
* 「更新」ボタンでの編集、「今すぐ発行」「今すぐ無効」
* 大きな2つのボタンだけの**操作パネル画面**（`/panel`・音と表示で結果が分かる）
* 同じ番号が複数の場所で有効になっていたら、終了時にまとめて削除
* 認証パッドに実際に入っている番号の一覧表示と個別削除
* 実行ログ

対象環境: macOS（Intel MacBook Pro でも動きます）／ Python 3.11 以上

---

## 最初に：認証情報を作り直してください

チャットに貼られたトークンとシークレットキーは、そのまま使わないことを強くおすすめします。
SwitchBot アプリの開発者向けオプションで**再発行**してから `.env` に入れてください。
このトークンは玄関の鍵を作り放題にできる権限そのものです。

## セットアップ

```bash
cd switchbot_keypad_scheduler
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# .env を開いて SWITCHBOT_TOKEN / SWITCHBOT_SECRET / SWITCHBOT_DEVICE_ID を書く
```

前提として、SwitchBot アプリで認証パッドの**クラウドサービスを有効**にしておく必要があります
（無効だと API のデバイス一覧に出てきません）。

### 起動

```bash
python app.py
# → http://127.0.0.1:5058 をブラウザで開く
```

### 同じ Wi-Fi の iPad やスマホから開く

`.env` の `APP_HOST` を `0.0.0.0` にして、**必ず `APP_PASSWORD` も設定**してください。

```
APP_HOST=0.0.0.0
APP_PASSWORD=好きな合言葉
```

起動すると、つなぎ先の URL が表示されます。

```
  管理画面 : http://127.0.0.1:5058/
           : http://192.168.1.23:5058/    （同じ Wi-Fi の端末から）
  操作パネル: http://192.168.1.23:5058/panel
```

* 初回だけ合言葉を聞かれます。以後60日はその端末で入り直し不要です（`/logout` で解除）。
* Mac の IP は DHCP で変わることがあります。ルーターで固定するか、Apple 製端末なら
  `http://お使いのMac名.local:5058/panel` でも届きます（Mac 名は「システム設定 > 一般 > 情報」）。
* 初回起動時に macOS のファイアウォールが「接続を許可しますか」と聞いてきたら許可してください。
* 自宅・社内のネットワーク（192.168.x.x / 10.x.x.x / 172.16〜31.x.x）以外からのアクセスは、
  合言葉があっても既定で拒否します。外から使う必要がある場合だけ `ALLOW_REMOTE=1` にしてください。
* **ルーターのポート開放はしないでください。** 外から使いたい場合は Tailscale などの VPN 経由にしてください。
  この画面はドアの暗証番号を作れるので、インターネットに直接出すのは危険です。

`APP_PASSWORD` を空のままにできるのは、`APP_HOST=127.0.0.1`（この Mac だけ）で使うときだけです。
LAN に公開したまま合言葉が空だと、起動時に警告を出します。

## 操作パネル（/panel）

玄関脇の iPad や古いスマホに出しておく用の画面です。設定機能はなく、
**「パスコード有効」「パスコード無効」の2つのボタンだけ**が並びます。

* ボタンを押すと**合成音声で「パスコード有効」「パスコード無効」と読み上げます**。
  あわせて短い効果音が鳴り、画面全体の色と大きな文字（有効／登録中／解除中／無効／エラー）が変わります。
* 認証パッドへの反映が確定した時点で「パスコードが有効になりました」「パスコードを無効にしました」と
  もう一度読み上げます（押した直後の発声と重なる場合は省略します）。失敗時は「エラーです」とブザー。
### 読み上げの声を良くする

読み上げは、起動時に macOS の `say` コマンドで作った音声ファイルを鳴らしています。
ブラウザ内蔵の読み上げよりも自然で、**iPad から開いても Mac の声で鳴ります**（音声は Mac 側で作って
配信するため、端末ごとの声の差が出ません）。`say` が使えない環境では、自動的にブラウザ内蔵の
読み上げに切り替わります。

```bash
say -v "?" | grep ja_JP        # 使える日本語の声を調べる
say -v Kyoko "パスコード、有効" # 実際に聞いてみる
```

気に入った声の名前を `.env` に書きます。速さは1分あたりの語数で、小さいほどゆっくりです。

```
APP_VOICE=Kyoko
APP_VOICE_RATE=175
```

#### 音声ファイルを自分で用意する（いちばん自然にできます）

読み上げる文言は7つで固定なので、好きな音声サービスで一度作ってファイルとして置くのがおすすめです。
実行時に API を呼ばないので、費用も通信もかかりません。`audio/custom/` に次の名前で置くだけです。

```
audio/custom/on.mp3        パスコード、有効
audio/custom/off.mp3       パスコード、無効
audio/custom/on_done.mp3   パスコードが有効になりました
audio/custom/off_done.mp3  パスコードを無効にしました
audio/custom/busy.mp3      解除中です。少しお待ちください
audio/custom/error.mp3     エラーです
audio/custom/test.mp3      音声オン
```

拡張子は `.mp3` `.m4a` `.wav` `.ogg` `.opus` `.aac` `.aiff` のどれでも構いません（大文字小文字は不問）。
置いたものが優先され、足りない分だけ `say` が使われます。文言は `phrases.py` にまとまっています。

**置いても `say` の声のままのとき**は、まず**アプリを再起動**してください（音声の割り当ては起動時に
決まります）。起動時にどれが使われるか一覧が出ます。

```
読み上げ音声（/Users/.../audio/custom に置いたファイルを優先します）
  on        自作 on.mp3
  off       say（Kyoko）          ← 拾えていない
  ...
  [無視] off_done .mp3（ファイル名が違います）
```

`[無視]` が出ていればファイル名の問題です（余分な空白、`on (1).mp3`、`.txt` など）。
ブラウザからは `http://127.0.0.1:5058/api/voice` でも確認できます。URL が `/audio/custom/...`
になっていれば正しく拾えています。それでも古い声が鳴る場合は、パネルの画面を
スーパーリロード（⌘+Shift+R）してください。

**Google Cloud Text-to-Speech で作る**場合は、同梱のスクリプトが使えます。

```bash
# 1. Google Cloud で「Cloud Text-to-Speech API」を有効にする
# 2. 「APIとサービス > 認証情報」でAPIキーを作り、そのキーを開いて
#    「APIの制限」で "Cloud Text-to-Speech API" を選んで保存する
export GOOGLE_TTS_API_KEY=作ったキー

# 3. 日本語の声を一覧
python make_voice_google.py --list

# 4. 好きな声で7ファイル作る（audio/custom/ に入ります）
python make_voice_google.py --voice ja-JP-Chirp3-HD-Aoede --rate 0.95
```

`403 ... are blocked`（`API_KEY_SERVICE_BLOCKED`）が出たら、上の手順2の「APIの制限」が
設定されていません。キーの制限一覧に Text-to-Speech を追加してください（反映に数分かかります）。
APIキーを使わず gcloud の認証で通すこともできます。

```bash
gcloud auth login && gcloud config set project プロジェクトID
unset GOOGLE_TTS_API_KEY     # APIキーが無いときは自動でこちらを使います
```

`Chirp 3: HD` や `Gemini-TTS` 系の声は、macOS の Kyoko とは比較にならないほど自然です。
全部で60文字ほどしか使わないので、無料枠に収まります（正確な料金は Google Cloud の
料金ページで確認してください）。文言を変えたいときは `--text on="パスコードが使えます"` のように
指定できます。

コードを書かずに済ませたい場合は、**Google AI Studio** の音声生成でテキストを入力して
音声をダウンロードし、上の名前に変えて `audio/custom/` に置いても同じです。

#### macOS のプレミアム音声を入れる

1. 「システム設定 > アクセシビリティ > 読み上げコンテンツ」を開く
2. 「システムの声」のポップアップから **「声を管理…」**（古い macOS は「カスタマイズ…」）
3. 日本語の項目を開き、**Kyoko / Otoya の（プレミアム）** にチェックを入れてダウンロード（数百MB）
4. 増えた名前を確認する

```bash
say -v "?" | grep ja_JP
# Kyoko            ja_JP
# Kyoko (Premium)  ja_JP    ← これが増えている
```

5. 全部聞き比べる

```bash
say -v "?" | grep ja_JP | sed 's/ *ja_JP.*//' | while read -r v; do
  echo "$v"; say -v "$v" "パスコード、有効"; sleep 1
done
```

6. 気に入った名前を `.env` に書く（空白を含むので引用符で囲むと確実です）

```
APP_VOICE="Kyoko (Premium)"
```

7. アプリを再起動すれば音声ファイルが作り直されます

**Siri の声（Siri Voice 1〜5）は `say` からは使えません。** システム設定の一覧には出てきますが、
`say` や読み上げ機能とは別系統で、指定しても `Voice not found` になります。狙うのは
「（プレミアム）」または「（拡張）」と書かれたほうです。

声の名前を間違えると起動時にこう出て、ブラウザ内蔵の読み上げに切り替わります。

```
[WARN] 読み上げ音声を作れませんでした（APP_VOICE=Kyoko）: Voice `Kyoko' not found.
       使える日本語の声: Kyoko / Kyoko (Premium) / Otoya
       ブラウザ内蔵の読み上げに切り替えます。
```

声・速さ・読み上げる文言を変えたら、アプリを再起動するだけで音声ファイルが作り直されます
（古いファイルは自動で消えます）。文言は `app.py` の `PHRASES` にまとまっています。
「パスコード、有効」と読点を入れているのは、そのほうが間が自然に聞こえるためです。

iPad / iPhone では最初のタップから音が出せるようになります（右下の「音 オン」を一度押しておくと、
本番の操作より前に解錠できます）。
* 右下の「音 オン」で音声と効果音をまとめて消せます。
* どの番号を操作するかは**管理画面で決めます**。スケジュールの編集フォームで
  「この番号を操作パネルで扱う」にチェックを入れてください（指定できるのは1件だけです）。
* 有効化したときの有効時間も同じフォームで指定します（既定120分）。時間が来れば自動で消えます。
* **押すと「直近のスケジュールの前倒し開始」になります。** 同じ番号のスケジュールが
  いま開いている、または2時間以内に始まる場合、その回を**開始時刻だけ前倒しした扱い**で発行します。
  終了時刻は元のスケジュールのままです。発行はひとつだけなので、パネルからスケジュールへの
  切り替わりで番号が使えなくなる時間は発生しません。

  | パネルを押したとき（予定は 18:25〜21:00） | 結果 |
  | --- | --- |
  | 18:00（2時間以内） | 予定を前倒しで開始。**21:00 まで** |
  | 19:30（予定の最中） | すでに有効なので何もしない |
  | 16:00（2時間より前） | 予定とは無関係の番号として 120分（18:00 まで） |
  | 09:00（予定なし） | 120分（11:00 まで） |

  120分の部分は、スケジュールごとの「パネルで有効化したときの有効時間」で変えられます。
* **無効ボタンはスケジュールより優先されます。** 予定の最中でも押せば即座に消え、
  その回は自動では復活しません（翌日以降の回は通常どおり動きます）。
  もう一度使いたいときは、もう一度「パスコード有効」を押してください。
* 管理画面の「今すぐ発行」も同じ動きになります。

## 同じ番号を複数のスケジュールで使う

同じ番号を使う項目は、**時間帯が重ならなければ**登録できます（例：朝 07:00〜09:00 と 夜 19:00〜21:00）。
重なる場合は保存時に弾きます。認証パッドは同じ番号を二重に登録できないためです。

有効時間の終了時には、**同じ番号で有効になっているものをすべて同時に削除**します。
操作パネルから出した番号とスケジュールの番号が同じなら、片方が終わればもう片方も消えます。
ただし、消された側のスケジュールの時間帯がまだ残っている場合は、削除の反映を待ってから
自動で登録し直すので、その日の予定が丸ごと消えることはありません。

## 使い方

右側のフォームに、名前・パスコード（6〜12桁）・繰り返し・時間帯を入れて「追加する」。
カードの「編集」を押すとフォームに読み込まれ、ボタンが「更新する」に変わります。

| ボタン | 動作 |
| --- | --- |
| 今すぐ発行 | その番号を即座に登録（有効期限は今日の終了時刻まで） |
| 今すぐ無効 | そのルールで登録済みの番号を即座に削除 |
| 停止 / 再開 | スケジュールの一時停止。登録済みの番号は終了時刻に削除されます |
| 削除 | ルールと、登録済みの番号の両方を削除 |
| 今すぐ同期 | 認証パッドの番号一覧を取り直す |

画面右上の「操作パネルを開く」から `/panel` に移動できます。

### パスコードの種類

* **期限付き（timeLimit・推奨）** … 認証パッド自身が開始・終了時刻を持ちます。万一 Mac が落ちていても
  時間外に開くことはありません。終了後、このアプリが後片付けとして削除します。
* **常時有効（permanent）** … 登録した瞬間から使えます。終了時刻の削除はこのアプリ任せなので、
  Mac が動いていないと無効化されません。特別な理由がなければ「期限付き」を使ってください。

### 「何分前に登録するか」

SwitchBot の登録コマンドは非同期で、実際に認証パッドへ届くまで1分ほどかかります。
既定の10分前にしておけば、開始時刻には確実に使える状態になります。

## Mac を閉じても動かすために

このアプリは**Mac が起きていないと動きません**（クラウド上のスケジューラではありません）。

* スリープ抑止つきで起動する: `caffeinate -is python app.py`
* 自動起動させる: `~/Library/LaunchAgents/local.switchbot-keypad.plist` を作り
  `launchctl load` する。`ProgramArguments` に `.venv/bin/python` と `app.py` の絶対パスを書きます。
* 省エネルギー設定で「電源接続時はスリープさせない」も併せて有効にしてください。

期限付きパスコードを使っていれば、Mac が止まっても「開けっぱなし」にはならず、
「その日の発行が行われない」だけで済みます。

## 仕組みと、SwitchBot API 側の制約

このアプリの設計は、次の API 仕様をそのまま反映しています。

1. `createKey` / `deleteKey` は**非同期**です。HTTP 応答は `commandId` を返すだけで、成否は分かりません。
2. `createKey` の応答には**パスコード ID が含まれません**。しかし `deleteKey` には ID が必須です。
3. そのため、`GET /v1.1/devices` が返す認証パッドの `keyList`（`id` / `name` / `status` / 暗号化された
   `password`）を**60秒ごとにポーリング**し、登録時に付けた一意な名前をキーに ID を回収しています。
   名前は `R{ルールID}{名前}-{日付}-{開始時刻}` の形で自動生成されます（SwitchBot アプリでもこの名前が見えます）。
4. `keyList` の `password` はシークレットキーを鍵とした AES-128-CBC で暗号化されています。画面の
   「認証パッドに入っている番号」では復号して表示します（復号できない場合は `＊＊＊＊`）。
5. API は**1日1万回**まで。このアプリは1分あたり1回程度（1日約1,500回）しか呼びません。

30秒ごとの判定はすべて SQLite の状態を見て行うので、アプリを再起動しても二重発行や取りこぼしは起きません。

## 気をつける点

* **同じ番号は同時に登録できません。** 時間帯が重なる場合のみ保存時に弾きます。
* 発行が SwitchBot 側でタイムアウトした場合、その日は自動で再試行しません。ログに `発行失敗` が出たら
  「今すぐ発行」を押してください（既知の不安定さで、まれに webhook も応答も来ないことがあります）。
* 認証パッドが電池切れ・Hub と切れている状態では登録も削除も届きません。
* `data.sqlite3` にパスコードが平文で入ります。`.env` `secret.key` と合わせて共有・コミットしないでください。
* 誰がいつ開けたかの記録は API から取れません（SwitchBot アプリの履歴で確認してください）。
* パネルで有効化した番号がスケジュールの開始時刻をまたぐと、スケジュール側は二重登録を避けて
  何も送りません（終了時刻はすでにスケジュールに合わせて短縮されているため）。このときカードには
  「端末に登録済（パネル/手動）」と表示されます。

## うまく動かないとき

**`keyList 取得に失敗: 通信エラー ... Failed to resolve 'api.switch-bot.com'`**

Mac が一時的にインターネットに出られていません（スリープ復帰直後、Wi-Fi の切り替わり、VPN、
DNS の不調など）。アプリは止まらず、回線が戻れば次の同期で自動的に復帰します。

* 通信エラーは、その場で2回まで自動的に粘ります（1.5秒・3秒あけて再試行）
* それでも駄目な場合、一覧の同期はスキップされ、直前の状態を保ちます
* 発行に失敗した回は、時間帯が残っていれば3分後に自動で作り直します
* 削除に失敗した回も、3分ごとに再送します

繰り返し出るなら Mac 側の問題です。`ping api.switch-bot.com` や
`scutil --dns | head` で名前解決を確認してください。スリープ復帰後に頻発する場合は、
「システム設定 > ロック画面」で電源接続時のスリープを切っておくと安定します。

**`sqlite3.OperationalError: unable to open database file`**

`data.sqlite3` を置くフォルダに手が届いていません。よくある原因は次の3つです。

1. アプリの起動中にプロジェクトフォルダを移動・リネームした（→ 再起動すれば直ります）
2. `data.sqlite3` の所有者が別ユーザー（`sudo` で起動した名残など）
3. フォルダに書き込み権限がない。SQLite は本体のほかに `-wal` / `-shm` を同じ場所に作るため、
   読み取りだけでも書き込み権限が要ります

```bash
cd ~/python/switchbot_keypad_scheduler
ls -la data.sqlite3* .          # 所有者を確認
touch _t && rm _t && echo 書き込みOK
sudo chown "$(id -un)":staff data.sqlite3*   # 2 の場合
```

置き場所を変えたいときは `.env` に `APP_DB_PATH=/絶対パス/data.sqlite3` を設定してください。
iCloud Drive や共有フォルダの中は、同期と競合して壊れることがあるので避けてください。

## ファイル構成

```
app.py             Flask アプリと API、スケジューラ起動
scheduler_core.py  時刻判定と発行／削除の実行エンジン
switchbot_api.py   SwitchBot OpenAPI v1.1 クライアント（署名・createKey・deleteKey・復号）
store.py           SQLite（ルール／発行履歴／ログ）
templates/index.html  管理画面
templates/panel.html  操作パネル（大きな2ボタン）
secret.key            ログイン維持用の鍵（初回起動時に自動生成）
selftest.py        偽クラウドを相手にした自己テスト
phrases.py         読み上げる文言
make_voice_google.py  Google Cloud TTS で読み上げ音声を作るスクリプト
audio/custom/      自分で用意した音声ファイルの置き場所
```
